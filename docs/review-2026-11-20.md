# 项目评审总案 — 功能 / UI / UX 改进清单（三模型并行评审）

> 评审方式：三个模型并行、各管一摊 —— Opus（NotchMind 原生 HUD 设计评审）、Sonnet-1（Python 管线功能架构）、Sonnet-2（Workbench Web UI）。
> 本清单是三份报告的合并收敛版，供 Claude 与 Antigravity 分工实施。分工建议见 `docs/antigravity-handoff.md`。

## 跨侧共识（三方独立发现，优先级最高）

1. **安全默认值失守**：`app.py` 开放 `Access-Control-Allow-Origin: *` + `frame-ancestors *`，任意网页可跨域读取全部知识条目、触发同步、开关剪贴板监测（app.py:261-264, 307-321）；NotchMind 侧 `allowScreenRecording` 默认 `true`（SettingsStore.swift:164），防自采保险默认失效。**两处一起修，属于同一个「默认信任边界」问题。**
2. **长任务反馈断裂**：Gemini 漫长等待（3-10s 甚至挂死）在三个界面（刘海收起态、Workbench、B站同看）都无阶段反馈，错误态要么不可见要么锁死。三份报告各自从不同角度撞上了它。
3. **轮询/并发竞态**：Workbench 6s 全量重渲染打断用户操作 + toggle/submit 无防抖（app.py:148-151, 158-175 无锁）；Python 侧剪贴板轮询线程被同步调用阻塞。

## P1 — 明显改进

**Python 侧**
- `.env` 写入非原子无锁，并发 `POST /api/model` 可截断丢 API Key（engine.py:73-90 → 复用 `_atomic_write_text` + 锁）
- HN 每轮固定 46 个请求且去重在抓取后（hackernews.py:14-26 → 先过滤已知 id，`httpx.HTTPTransport(retries=2)`）
- `/api/state` 每 6s 全量盘 IO、entries.json 无分页缓存（app.py + obsidian.py:29 单全局锁串行）
- collector 采的 `published_at` 全链路无人使用，`summary` 被截 80/120 字（要么用于时效过滤，要么删字段）
- `WORKBENCH_BASE_URL` 写死 8765 而端口可 `--port` 改（obsidian.py:27）
- capture 完成回执塞进 sync 槽，前端从未读 `last_capture_status`（app.py:181-183）
- submit_capture 无 running 闸，连点起无限线程；每次 capture 新建 genai.Client 无复用（app.py:158-175）

**NotchMind 侧**
- `.clear` 档 scrimAlpha=0.10，白壁纸下对比度约 1.25:1，远不达 4.5:1（NotchSurface.swift:83 → 下限提至 0.24）
- `NotchIconView.swift:42-50` 高饱和青蓝渐变图标 + 青色发光，直接违反自家 DESIGN.md「严禁 Cyan」（→ 单色银白高光）
- 等待 Gemini 无阶段化反馈：截屏中→提炼中→已写入，收起态右耳给脉冲进度；成功后自动 Peek 展开 2.5s 形成正向闭环（CompanionEngine.swift:152, 462）
- 外接屏 `topLeading/topTrailing` 窗口级+视图级双重偏移，展开动画锚点错位（HUDWindowController.swift:215-228 + NotchHUDView.swift:67-77 → 视图层统一 `.top`，窗口级管左右）
- Settings 标签流不换行、xmark 字号 9pt 低于自家 11pt 下限（SettingsView.swift:302-329 → FlowLayout + 11pt）

**Workbench 侧**
